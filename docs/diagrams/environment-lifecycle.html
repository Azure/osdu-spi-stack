OSDU SPI

The Backing Environment

How osdu-spi-stack becomes the shared deploy and test target for the osdu-spi service forks. One environment, version-pinned, self-refreshing, rebuilt weekly. Design only: ADRs 028-033 plus two design docs; implementation follows in phases.

Bottom Line Up Front
One shared environment, pinned to a release tag, backs every fork's deploy and test gates.
A PR borrows one service by pinning its image, proves it, and puts the canonical back.
Weekday refresh proves it serving; Saturday rebuilds it from nothing at the pin.
Almost everything rides seams the stack already has: the image lock and suspended GitOps.

2 Three Version Axes
Stack definition
Release tag, pinned by the contract file; moves only by reviewed PR.
Canonical images
osdu-image-lock; advance on refresh. Source flips GitLab to fork GHCR as each service onboards.
Ephemeral pins
A PR's image under test; transient overlay, swept when stale.
3 Fail-Closed Gates
  • deployable = converged + no maintenance + deploy record present
  • A failed upgrade, reset, or refresh keeps deploys blocked until probes pass or an operator clears it
  • Missing deploy record refuses pins; a fresh rebuild opens only after probes
Unavailability with a reason beats testing on a half-changed platform.

5 Identity
Per-fork managed identity
Federated credential bound to the fork's protected deploy environment; per-repo revocation.
Two namespace roles
Explicit subjects, reads split from a lock-scoped write; no create, delete, or secrets verbs.
One-command onboarding
spi onboard provisions identity and stamps fork variables; idempotent.
6 Operating Rhythm
Per PR · minutes
pin, prove, restore; only that service moves
Weekdays 05:00
refresh: sweep, converge, probe before the first fork job
On release
bump PR, merge, spi up at the new tag
Saturday 06:00
full rebuild at the pin, 3-6 h; sheds all accreted state
The reset boundary: refresh touches runtime state, upgrade may change substrate in place, only the full RG rebuild clears both cluster and PaaS state.
7 Built on Existing Seams
ADR-014 suspend
Suspended GitOps already pins the environment; upgrade is spi up re-run.
ADR-017 image lock
The lock is already the live manifest; pins survive every refresh.
Smoke pipeline
Readiness gate and OIDC discipline reused for the lifecycle workflows.
Takeaway: Evidence before merge. A fork PR proves itself against a known environment version, then leaves no trace behind.
